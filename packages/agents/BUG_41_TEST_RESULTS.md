### Bug #41: File Path Normalization 🔴 NOT FIXED
**Status**: 🔴 Still showing only filenames

**Evidence**:
```markdown
**Location**: `MetadataVersion.java` (Line 46)
**Location**: `OAuthBearerLoginCallbackHandler.java` (Line 25)
**Location**: `Graph.java` (Line 109)
```

**Expected**:
```markdown
**Location**: `server-common/src/main/java/org/apache/kafka/server/common/MetadataVersion.java` (Line 46)
```

**Root Cause Analysis**:
The normalization code IS working (confirmed in code review), but the **data coming IN** only has filenames, not full paths!

**Where the problem originates**:
1. Tool output (PMD, Checkstyle) contains full paths: `/workspace/server-common/src/.../MetadataVersion.java` ✅
2. Issue grouping preserves full paths ✅
3. **BUT**: `exampleIssue` selection logic picks issues where `file` field is just filename ❌

**Real Fix Needed**:
The problem is in `groupIssues()` or `generateGroupSection()` - when selecting the `exampleIssue`, it's picking issues where the `.file` field contains only the basename, not the full path.

**Code location**:
```typescript
// packages/agents/src/two-branch/analyzers/v9-grouped-report-formatter.ts
// Lines 2380-2397

// BUG FIX #30: Improved code example section
let exampleIssue: EnrichedIssue | undefined = representative;

// The problem: `representative` (first issue in group) has filename-only
// Even when trying to find better examples, all issues in groupIssues have filename-only
```

**Why this happens**:
The `groupIssues()` function (in `utils/issue-grouping.ts`) stores `issue.file` as-is. If the tool output has inconsistent paths (some full, some basename), the grouping preserves that inconsistency.

**Next Steps**:
1. Add path normalization in `test-v9-e2e-complete.ts` BEFORE categorization
2. Ensure ALL issues have full paths before grouping
3. Re-test

**Conclusion**: Bug #41 is **NOT FIXED** - needs deeper fix in data pipeline.
