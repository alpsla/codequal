## ❌ The Real Problem

The reports showing `PR #0` (v9-micronaut.md, v9-quarkus-FINAL.md, v9-spring-boot-FINAL.md) were **NOT** generated by any of the verified test files.

### Evidence:

1. ✅ **test-v9-lite-e2e.ts** - Passes prNumber correctly
2. ✅ **test-v9-multi-framework.ts** - Passes prNumber correctly
3. ✅ **test-v9-e2e-complete.ts** - Passes prNumber correctly
4. ✅ **v9-analyze.ts** API endpoint - Requires prNumber
5. ❌ **UNKNOWN SOURCE** - Generated reports with prNumber=0

---

## 🎯 Root Cause

There is an **external script, manual test, or production code** that is calling the V9 analyzer/formatter with either:
- `prNumber: 0`
- `prNumber: undefined` (falls back to 0 due to `metadata.prNumber || 0` pattern)
- No prNumber at all

### Where to Look:

1. **Oracle Cloud Deployment Scripts**
   - Check if there's a deployment script that runs analysis
   - Check environment variables or config files

2. **Manual Test Scripts**
   - Scripts that might not be in version control
   - One-off test runs
   - Scripts in user's home directory or /tmp

3. **CI/CD Pipelines**
   - GitHub Actions workflows
   - Jenkins jobs
   - Kubernetes cron jobs

4. **Direct Formatter Calls**
   - Code that bypasses `V9IntegratedAnalyzer.analyzeRepository()`
   - Direct instantiation of `V9GroupedReportFormatter` with incomplete metadata

## 🔧 Recommended Fixes

### Short-Term Fix: Add Warning

Add validation to warn when prNumber is missing:

```typescript
// header-sections.ts:58
if (!metadata.prNumber || metadata.prNumber === 0) {
  console.warn('[WARNING] PR number is missing or zero - report will show #0');
  console.warn('[WARNING] Stack trace:', new Error().stack);
}
header += `**Pull Request:** #${metadata.prNumber || 0}`;
```

This will log when and where the issue occurs.

### Long-Term Fix: Make prNumber Required

```typescript
// CompileReportInput interface

}
```
