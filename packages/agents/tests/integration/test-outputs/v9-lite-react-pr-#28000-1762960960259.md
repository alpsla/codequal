### 🟠 Javascript Lang Security Detect Child Process

**Severity**: HIGH | **Tool**: semgrep | **Found in**: 5 files | **Category**: EXISTING_REST

---

#### 📋 What is this issue?

The code uses the `child_process` module with a function argument `cmdArg` that is not sanitized, creating a command injection vulnerability. This allows an attacker to inject malicious shell commands if the input is user-controllable.

#### 🎯 Why does it matter?

An attacker can execute arbitrary system commands by manipulating the `cmdArg` input, potentially leading to full system compromise, data exfiltration, or denial of service. For example, if `cmdArg` contains `'; rm -rf /'`, it would execute the destructive command.

#### 🔍 Common causes:

- Direct use of `child_process.exec()` or similar functions with user-controllable input
- Lack of input validation or sanitization for the command argument
- Failure to use secure alternatives like `child_process.execSync()` with fixed commands

#### ⚠️ Impact if not fixed:

This vulnerability can result in complete system takeover, unauthorized data access, or destruction of critical system resources. It also violates security compliance standards like PCI DSS and GDPR by exposing the system to unauthorized command execution.

#### ⚡ Risk Assessment

**Overall Risk**: 🟠 **HIGH RISK**

High priority - could cause significant problems in production

**Category**: Security  
**Focus**: Protecting against attacks, vulnerabilities, and unauthorized access

#### 📍 Representative Example

**Location**: `fixtures/packaging/build-all.js` (Line 19)

**Code**:

```javascript
    16 |     cwd: path,
    17 |     stdio: 'inherit',
    18 |   };
>   19 |   const result = child_process.spawnSync(cmdArg.cmd, cmdArg.args, opts);
    20 |   if (result.status !== 0) {
    21 |     throw new Error(`Failed to build fixtures!`);
    22 |   }
```

#### 🔧 How to Fix

Replace direct `child_process` calls with a secure alternative. Use a whitelist of allowed commands or sanitize inputs using a library like `shell-quote`. Alternatively, avoid `child_process` entirely if possible and use safer system interaction methods.

**Recommended Code**:

```javascript
const { exec } = require('child_process');
const { escape } = require('shell-quote');

function runCommand(cmdArg) {
  // Sanitize input before executing
  const sanitizedCmd = escape([cmdArg]);
  exec(sanitizedCmd, (error, stdout, stderr) => {
    if (error) {
      console.error(`Error: ${error}`);
      return;
    }
    console.log(`Output: ${stdout}`);
  });
}
```

**Best Practices to Follow**:

- Avoid using `child_process` with user-controllable input
- Sanitize all user inputs using a proper shell escaping library
- Use a whitelist of allowed commands instead of dynamic command construction
