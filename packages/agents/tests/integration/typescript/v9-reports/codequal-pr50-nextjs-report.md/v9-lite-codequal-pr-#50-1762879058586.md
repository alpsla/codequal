### 🟠 Javascript Lang Security Detect Child Process

**Severity**: HIGH | **Tool**: semgrep | **Found in**: 90 files | **Category**: EXISTING_REST

---

#### 📋 What is this issue?

The code uses child_process.exec() with a user-controllable command argument, creating a command injection vulnerability. The function accepts a 'command' parameter that is directly passed to exec() without sanitization or validation.

#### 🎯 Why does it matter?

An attacker can inject malicious shell commands by manipulating the command parameter. For example, passing 'ls; rm -rf /' would execute both commands. This allows arbitrary code execution on the server with the privileges of the running process, potentially leading to full system compromise.

#### 🔍 Common causes:

- Direct use of child_process.exec() with user input
- No input validation or sanitization of the command parameter
- Function parameter 'command' is not escaped or restricted

#### ⚠️ Impact if not fixed:

This vulnerability enables remote command execution, allowing attackers to execute arbitrary system commands. It can lead to complete system compromise, data theft, or service disruption. This violates security compliance standards like PCI DSS, HIPAA, and SOC 2.

#### ⚡ Risk Assessment

**Overall Risk**: 🟠 **HIGH RISK**

High priority - could cause significant problems in production

**Category**: Security  
**Focus**: Protecting against attacks, vulnerabilities, and unauthorized access

#### 📍 Representative Example

**Location**: `.claude/test-mcp-servers.js` (Line 9)

**Code**:

```javascript
     6 |   console.log(`\nTesting ${name} MCP server...`);
     7 |   console.log(`Command: ${command} ${args.join(' ')}`);
     8 |   
>    9 |   const child = spawn(command, args, {
    10 |     env: { ...process.env, ...env },
    11 |     stdio: ['pipe', 'pipe', 'pipe']
    12 |   });
```

#### 🔧 How to Fix

Replace child_process.exec() with child_process.execSync() or child_process.spawn() using a whitelist of allowed commands. Validate and sanitize all user inputs. Use a command whitelist approach where only predefined safe commands are allowed. If child_process is required, use shell-escape libraries to properly escape user input.

**Recommended Code**:

```javascript
const { execSync } = require('child_process');

function executeCommand(command) {
  // Whitelist approach - only allow specific commands
  const allowedCommands = ['ls', 'pwd', 'date'];
  if (!allowedCommands.includes(command)) {
    throw new Error('Command not allowed');
  }
  return execSync(command, { encoding: 'utf8' });
}

// Alternative: Use spawn with fixed arguments
const { spawn } = require('child_process');
function safeExecuteCommand(command, args) {
  const child = spawn(command, args);
  return new Promise((resolve, reject) => {
    let output = '';
    child.stdout.on('data', (data) => {
      output += data.toString();
    });
    child.on('close', (code) => {
      if (code === 0) resolve(output);
      else reject(new Error(`Command failed with code ${code}`));
    });
  });
}
```

**Best Practices to Follow**:

- Avoid using child_process.exec() with user input entirely
- Implement a strict command whitelist approach
- Use child_process.spawn() with fixed arguments instead of shell injection
