### 🟠 Javascript Lang Security Detect Child Process

**Severity**: HIGH | **Tool**: semgrep | **Found in**: 90 files | **Category**: EXISTING_REST

---

#### 📋 What is this issue?

The code uses the `child_process` module to execute system commands based on user-provided input, creating a command injection vulnerability. The `command` argument is passed directly into `exec` without any sanitization or validation.

#### 🎯 Why does it matter?

An attacker can inject malicious shell commands by manipulating the `command` input, potentially leading to arbitrary code execution, data exfiltration, or system compromise. For example, if `command` contains `'; rm -rf /'`, it would execute the deletion command.

#### 🔍 Common causes:

- Direct use of `child_process.exec` with user-controlled input
- Lack of input validation or sanitization before command execution
- No sandboxing or restricted execution environment for commands

#### ⚠️ Impact if not fixed:

This vulnerability allows remote attackers to execute arbitrary system commands with the privileges of the running application. It can lead to full system compromise, data loss, and violates security compliance standards like PCI DSS and GDPR.

#### ⚡ Risk Assessment

**Overall Risk**: 🟠 **HIGH RISK**

High priority - could cause significant problems in production

**Category**: Security  
**Focus**: Protecting against attacks, vulnerabilities, and unauthorized access

#### 📍 Representative Example

**Location**: `.claude/test-mcp-servers.js` (Line 9)

**Code**:

```javascript
     6 |   console.log(`\nTesting ${name} MCP server...`);
     7 |   console.log(`Command: ${command} ${args.join(' ')}`);
     8 |   
>    9 |   const child = spawn(command, args, {
    10 |     env: { ...process.env, ...env },
    11 |     stdio: ['pipe', 'pipe', 'pipe']
    12 |   });
```

#### 🔧 How to Fix

Replace direct `child_process.exec` calls with safer alternatives like `child_process.execSync` with strict input validation, or use a sandboxed execution environment. Sanitize all user inputs using allowlists or escape sequences before constructing commands.

**Recommended Code**:

```javascript
const { exec } = require('child_process');

function safeExecuteCommand(command) {
  // Validate and sanitize input
  if (!command || typeof command !== 'string') {
    throw new Error('Invalid command');
  }
  
  // Allowlist approach: only permit known safe commands
  const allowedCommands = ['ls', 'pwd', 'date'];
  const sanitizedCommand = command.trim();
  
  if (!allowedCommands.includes(sanitizedCommand.split(' ')[0])) {
    throw new Error('Command not allowed');
  }
  
  // Use execSync for synchronous execution with better control
  const { execSync } = require('child_process');
  return execSync(sanitizedCommand, { encoding: 'utf8' });
}

// Usage example
// const result = safeExecuteCommand('ls -la');
```

**Best Practices to Follow**:

- Avoid using `child_process.exec` with user input; prefer `execSync` with strict validation
- Implement allowlist-based command validation to restrict execution to known safe commands
- Use sandboxing or containerization for executing untrusted commands
